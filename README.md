# FRAUD CAP

Static site publishing fraud-detection methodology and fraud-prevention curricula. No
JavaScript, no external requests, no trackers, no forms, no build framework: plain HTML and
CSS, generated by a small dependency-free Node script from JSON content files.

## Requirements

Node.js 18 or later. No npm packages are installed; `build.js` and the scripts in `scripts/`
use only Node's built-in modules (`fs`, `path`, `crypto`, `child_process`). Building the
registry's zip downloads additionally requires a `zip` binary on the system `PATH`.

## Building the site

```
node build.js
```

Reads `content/*.json` and `content/initiatives/*.json` through the templates in `build.js`
and writes static HTML into `initiatives/`, `how-to-use/`, `curricula/`, `about/`, and
`registry/`. The home page, `index.html`, is hand-authored and not templated.

## Updating the artifact registry

Registry artifacts live in `registry-source/<IDENTIFIER>/`, one directory per artifact, each
with a hand-edited `meta.yaml` and a `files/` directory holding the real deposit files.

```
node scripts/build-registry-metadata.js
```

Computes real SHA-256 hashes and byte sizes directly from the files on disk (never hand-typed),
rewrites each artifact's `files:` list in its `meta.yaml`, and writes the consolidated
`registry-source/registry.json` that `build.js` reads. Run this before `node build.js` whenever
an artifact's files or metadata change.

## Previewing every page at once

```
node build-preview.js
```

Combines every generated page into a single `preview.html` for quick review (each page in its
own `<iframe srcdoc>` to avoid CSS collisions). This file is a review tool, not part of the
published site.

## Generating sitemap.xml

The sitemap protocol requires absolute URLs, and this site is designed to work unmodified from
`file://`, a subpath, or a root domain, so no domain is hard-coded anywhere in the repo.
Generate `sitemap.xml` once the real deployment domain is known:

```
node scripts/build-sitemap.js https://your-real-domain
```

## Deployment

The entire repository root is the site: any static file host (GitHub Pages, S3, Netlify, a
plain web server) serving this directory works with no configuration, no environment
variables, and no server-side code. All internal links are relative, so the site also works
correctly opened directly from disk (`file://`) or served from a subpath rather than a domain
root.

## Directory structure

- `content/` — page content as JSON, kept separate from presentation.
- `registry-source/` — hand-edited artifact metadata and the real deposited files; not served
  directly (Tier 1 files are copied into `registry/<IDENTIFIER>/files/` at build time; Tier 2
  files never are).
- `assets/` — shared CSS, the favicon, and image assets.
- `build.js` — the template/render engine and build orchestrator.
- `build-preview.js` — the dev-preview combiner (not part of the published site).
- `scripts/` — the registry hash-generation script and the sitemap generator.

## Verification

Every page targets WCAG 2.1 AA. There is no automated test suite committed to the repo;
accessibility (axe-core + a heading-hierarchy check), full-site link crawling, and print output
have been verified manually against the built output during development.
